# Separate experiment plans, executions, and process records

An experiment plan describes reusable intent and expected methods, an experiment execution represents one actual run, and every process record belongs to exactly one execution. Plans remain freely editable without user-facing version management, while each execution starts from an independent baseline copied from the plan's design, implementation details, steps, parameters, and intended sample uses; copied values remain unconfirmed until the execution records what was actually completed, measured, or consumed. Later plan edits affect new executions only, so completed executions and reports retain their original context. The product groups screens and exports by this hierarchy; legacy records with missing or invalid execution ownership are repaired into an explicit historical execution instead of being silently omitted. The internal `ExperimentBatch` name remains temporarily for data compatibility, but user-facing language uses “实验执行”.
