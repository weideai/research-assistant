# R/LAB 工作台产品与交互审查

2026-11-22 · 对照 AI4H 项目书第七节及桌面工作区源码。下列观察来自修改前的界面和代码。本次在 Edge 中运行项目自带的演示数据，屏蔽外部网络。Windows 安装包、真实用户效果和独立审查仍待验证。

## 第一性原理

学生最容易忘记的是当时发生了什么，以及为什么这样解释一张图。实验当天应能用最少的输入留下观察，拿到原图时能补上证据，组会后能找回决定和下一步。用这三个动作决定首页入口、编辑顺序和开发优先级。

## 页面导引与 UI

1. **首次使用**。空工作区以“建立第一个项目”为主操作。创建成功后，在该项目里直接进入“记第一次实验”，无需回首页重新选择。对已有记录的用户，首页优先展示可继续编辑的记录，定稿记录使用“查看”。
2. **实验当天**。保留完整编辑页，为“记实际观察”“补原始文件”“写分析与下一步”提供页内直达入口。当前“实际过程与结果”在表单第六段。让赶时间的学生能够先记一句异常并确认保存，晚些时候接着写。
3. **准备组会**。从项目内选择几次实验，并排列日期、操作差异、结果与证据附件。每个摘要保留记录入口，AI 可以据此起草，缺失信息明确列为待核实。导师阅读导出件时也应看到能回溯的记录编号和附件名称。
4. **整合已有数据整理工具**。先选 WB 做一个完整样例，把同一次实验的原图、整理输出和实验记录连起来。整理默认另存产物，保留来源及处理时间，失败项可单独重试。能从结果图回到正确原图后，再扩展到其他实验类型。

## 对抗性走查

| 质疑 | 最小场景 | 通过依据 |
| --- | --- | --- |
| “已保存”能信吗？ | 输入一行观察后立即再点当前标签，然后离开并回来。 | 回来看到的文字与输入一致。若保存失败，输入仍可见且状态明确。 |
| 凭一张结果图真能找到正确原图吗？ | 两条记录各有同名原图，其中一条有裁剪图。让未参与整理的人从裁剪图开始找。 | 能确认唯一来源及对应实验。缺少关联时，明确提示补关联。 |
| 选一条记录，模型究竟看到了什么？ | 先用 A、B 两条合成记录讨论，在同一会话缩小到 B，另与全新会话作对照。 | 能说明是否包含历史消息，并在发送前知道实际范围；新会话仅含当前声明的内容。 |
| 导师提的事能追到上次实验吗？ | 项目中有两次同名实验，只给其中一次新建补做任务。 | 从待办或日历返回正确实验，已完成任务仍保留来源。 |
| 教学价值能观察到吗？ | 给一名首次使用者一张组会结果图，请其找到原图、说明一处条件差异并记下一个未决问题。 | 记录在哪一步停住、用了多久、是否需要指导。试用前不宣称已节省时间。 |

## 实施顺序

先保护编辑内容与 AI 来源选择，再打通“记录 → 原图”和“记录 → 后续任务”。随后改善首页、记录页的操作顺序，以一次真实组会验证。优先复用桌面服务和已有文件、任务命令；涉及新增证据关系时再单独设计数据迁移。独立验收时应在实际拟演示的安装包上重走核心流程。
