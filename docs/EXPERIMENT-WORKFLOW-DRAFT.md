# 实验计划管理软件：实验室逻辑草案

状态：草案。本文把当前已确认的边界和推荐的最小实验室流程整理成一份落地基线；在开始改数据库和页面前，以它作为实现依据。

## 1. 产品边界

工作台只解决四件事：

1. 实验设计与计划
2. 实验执行与数据保存
3. 实验报告管理
4. 周报管理

不建设统计分析、分析结果管理、样本库存、仪器管理、审批合规或实验室行政管理。设备名称可以写在计划或记录正文中，但不产生仪器台账。分析图表、统计表和脚本输出如果需要保存，只作为结果文件上传。

## 2. 最小真实实验室流程

```text
实验设计与实施计划
        |
        v
创建一次实验执行（复制执行基线）
        |
        +--> 按步骤执行、填写过程记录、保存结果文件
        |
        v
实验报告（单条记录 / 单次执行 / 整个实验）
        |
        v
周报（从实验记录和结果文件整理进展）
```

### 2.1 实验计划

一个实验计划由两个部分组成，但在软件中是一个对象：

**实验设计**

- 实验目的
- 实验原理或背景
- 实验组与对照组（可添加多行）
- 观察指标或预期结果
- 成功判定标准
- 补充说明

**实施计划**

- 负责人、计划开始和结束日期
- 样本与材料要求
- 计划参数表：参数名、目标值、单位、说明
- 有顺序的计划步骤：名称、操作说明、计划日期、执行人
- 过程记录默认内容：条件、过程、备注

计划可以随时修改，不维护用户可见的计划版本，也不提前规定将来会产生哪些结果文件。

### 2.2 实验执行

一次执行代表一次真实的实验工作，拥有执行编号、重复序号、分组、人员、实际日期和状态。

创建执行时复制一份“执行基线”：当时的实验设计、实施计划、计划步骤、计划参数和计划样本用途。执行人员可以在执行中增删改步骤、修正参数和样本用量；这些修改只属于本次执行，不回写计划。

计划后续可以继续自由修改。新执行使用新计划，旧执行和旧报告保留创建时的执行基线。

### 2.3 过程记录

一条过程记录是一次执行中的时间日志，不强制一条步骤对应一条记录。记录可以选择关联一个执行步骤，也可以作为执行级通用记录。

最小字段：

- 日期时间、实验人员
- 关联执行步骤（可选）
- 本次条件
- 操作与观察
- 实际参数（可添加多行）
- 异常或备注
- 结果状态：待确认、成功、失败
- 关联结果文件

执行步骤负责回答“计划中的这一步是否完成”；过程记录负责回答“这次实际发生了什么”。步骤完成时可以顺手创建记录，但不强制创建。

### 2.4 实验结果资料

结果资料只作为文件保存，不建立分析结果对象。文件可以是图片、表格、文档、原始数据或其他格式。

- 实验计划拥有统一的结果文件中心。
- 文件实际产生时再创建文件夹或选择已有文件夹。
- 文件必须关联来源实验执行，或者标记为实验级汇总。
- 文件夹名称、类型标签和说明由用户自定义，可跨多个执行统一浏览。
- 托管文件复制到工作台；大型原始数据可以保存为外部路径链接。

推荐的默认文件夹只是快捷建议，不是固定枚举：`原始数据`、`结果图片`、`表格`、`报告文档`、`其他`。

### 2.5 实验报告

报告不是另一套实验数据，而是对计划、执行、过程记录和结果文件的阅读与导出视图。

单条过程记录报告包含：

1. 实验和项目基本信息
2. 执行编号、日期、人员和记录状态
3. 实验目的（来自执行基线）
4. 条件与操作观察
5. 结果状态和人工填写的备注/结论
6. 本次执行步骤及完成状态
7. 实际参数
8. 结果文件缩略图、文件夹和完整文件入口

单次执行报告包含：执行概览、执行基线、实际步骤、实际参数、样本使用、过程记录索引和结果文件清单。

实验级报告包含：当前计划设计、计划步骤和参数、全部执行汇总、过程记录索引、结果文件夹和导出时间。不包含自动统计或分析章节。

报告在线视图使用执行基线保证历史上下文稳定；结果文件可在执行结束后继续补充。PDF/DOCX/Markdown/ZIP 是导出时的文件快照。

### 2.6 周报

周报只管理实验进展和沟通材料：

- 从日期范围选择实验计划和执行
- 汇总本周新增过程记录、执行状态、未完成步骤和结果文件
- 生成或上传 PPTX/PDF 等周报文件
- 保存报告日期、覆盖周期、项目、状态、摘要、反馈和修改日常

周报不承担实验数据分析。生成的 PPTX 和上传的原始周报都进入周报资料库。

## 3. 软件对象映射

| 业务概念 | 当前模型 | 落地要求 |
|---|---|---|
| 科研项目 | `ResearchProject` | 保留，作为多个实验计划的容器 |
| 实验计划 | `Experiment` | 增加实验设计字段，保留实施计划字段 |
| 实验执行 | `ExperimentBatch` | 创建时生成完整执行基线 |
| 计划步骤 | `ExperimentStep` | 只描述计划，不保存完成状态 |
| 执行步骤 | `BatchStep` | 从计划复制，可增删改和标记完成 |
| 计划参数 | `ExperimentParameter` | 作为执行基线的预期值 |
| 实际参数 | `BatchParameter` / `RecordParameter` | 执行中确认或测得的值 |
| 过程记录 | `ExperimentRecord` | 增加可选执行步骤关联，保留草稿/定稿/修订 |
| 结果资料 | `ExperimentAttachment` | 支持实验级文件夹、来源执行或实验级汇总 |
| 实验报告 | 阅读视图和导出服务 | 统一使用执行基线和当前结果文件 |
| 周报 | `WeeklyReport` / `WeeklyReportUpdate` | 保留上传、生成、反馈和修改时间线 |

## 4. 文书矩阵

| 产生位置 | 文书 | 格式 | 内容来源 |
|---|---|---|---|
| 过程记录保存后 | 单条记录报告 | 页面、PDF、DOCX | 执行基线、记录、实际参数、关联文件 |
| 实验计划页 | 实验级报告 | Markdown、PDF、DOCX、XLSX、JSON、ZIP | 计划、全部执行、过程记录、结果资料 |
| 报告列表批量导出 | 所选报告包 | ZIP + PDF/DOCX + 清单 | 用户选中的过程记录 |
| 周报页生成 | 实验周报 | PPTX | 日期范围内的执行、记录、步骤和图片 |
| 周报上传 | 周报资料库条目 | 原始 PPTX/PDF/ODP/KEY 等 | 用户上传文件和人工填写元数据 |
| 项目页归档 | 项目包 | `.ralab` ZIP | 项目结构、实验数据、托管附件、外部链接元数据 |

报告模板先只做内容结构一致、视觉样式可选。`科研档案`、`实验记录本`、`简洁结果报告`暂不扩展成三套业务逻辑。

## 5. 当前代码的主要落地点

1. `batch_create()` 目前只复制计划样本用途，必须同时复制设计快照、计划参数和计划步骤。
2. `ExperimentBatch` 目前没有保存执行创建时的设计内容，需要增加执行基线字段或独立快照结构。
3. `ExperimentRecord` 目前把条件、过程、结果、结论和备注压缩在少数字段中，需要补充可选步骤关联并重新整理表单文案。
4. `ExperimentAttachment` 目前强制属于过程记录，需要支持实验计划级文件夹以及“来源执行/实验级汇总”标记。
5. 实验报告需要以执行基线为上下文，避免计划后续修改改变旧执行的目的和步骤。
6. 周报生成、周报上传和周报资料库需要打通，生成后的 PPTX 应能直接归档。

## 6. 实施顺序

### P0：数据模型和执行基线

- 增加实验设计字段。
- 创建执行时复制完整执行基线。
- 保留旧数据兼容导入，并为历史执行生成明确的历史基线。

### P1：实验计划与执行页面

- 将计划详情分为“实验设计”“实施计划”“实验执行”三个清晰区域。
- 执行详情显示基线、实际步骤、实际参数、样本和过程记录。
- 计划修改不改变已创建执行的基线。

### P2：过程记录和结果文件

- 过程记录支持可选步骤关联和实际参数。
- 文件中心改为实验统一视图，支持文件夹、类型标签、来源执行和实验级汇总。
- 定稿记录保留修订原因和前后差异。

### P3：报告和周报

- 统一页面、PDF、DOCX、Markdown 的报告字段来源。
- 实验级报告不再加入分析结果章节。
- 生成 PPTX 后提供直接归档到周报资料库的动作。

## 7. 自问自答

**为什么不做分析结果模块？**

当前目标是可靠保存实验计划、原始数据和人工结论。分析工具和脚本可以独立使用，结果文件上传即可，避免把软件做成统计平台。

**为什么计划可以自由改？**

用户不需要管理复杂的计划版本；执行创建时保存完整执行基线，既保持计划编辑自由，又不会改写旧执行的实验上下文。

**为什么结果文件夹放在实验计划下？**

用户需要看到一个实验的全部资料，但每个文件仍保留来源执行，兼顾浏览便利和基本追溯。

**为什么过程记录不强制绑定步骤？**

真实实验中一条记录可能覆盖多个操作，也可能记录临时异常；步骤关联可选能保留时间线而不增加录入负担。
